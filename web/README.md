# fstool web UI

A static, client-side single-page app that runs fstool as WebAssembly. Upload
an archive or disk image, browse what's inside, extract individual files, and
convert the whole thing to another format — all in the browser. Nothing is
uploaded; every byte is processed locally in WebAssembly memory.

## Architecture

```
web/
├── index.html      layout
├── style.css       theme (light/dark aware)
├── app.js          UI controller (main thread)
├── worker.js       Web Worker — owns the wasm module + open image
└── pkg/            generated by wasm-bindgen (git-ignored, built by CI)
```

The wasm lives in a Web Worker so heavy inspect/convert work never freezes the
UI. The worker exposes fstool's in-memory API (`crate::memconv`):

- `probe(bytes)` → outer compression, partition table, or top-level FS kind
- `new Image(bytes)` / `Image.openPartition(bytes, n)` → an opened image
- `image.list(path)`, `image.readFile(path)`, `image.convert(target)`
- `supported_targets()` → the conversion menu

## Building locally

Requires the `wasm32-unknown-unknown` target and a matching `wasm-bindgen-cli`
(pinned in `crates/fstool-wasm/Cargo.toml`).

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.121   # match the crate version

# from the repo root:
cargo build --release --target wasm32-unknown-unknown \
  --manifest-path crates/fstool-wasm/Cargo.toml
wasm-bindgen --target web --no-typescript \
  --out-dir web/pkg \
  crates/fstool-wasm/target/wasm32-unknown-unknown/release/fstool_wasm.wasm

# serve it (ES modules + wasm need http://, not file://)
python3 -m http.server -d web 8099
# open http://localhost:8099
```

## Deployment

`.github/workflows/pages.yml` rebuilds `pkg/` and publishes `web/` to GitHub
Pages on every push to `master` that touches `src/`, `crates/fstool-wasm/`, or
`web/`.

## Limits

Everything is held in RAM, so practical input size is bounded by the browser
tab's memory (typically a few hundred MB). Formats hard-wired to `std::fs`
(qcow2, dmg) are not yet available in the browser — their backends need to be
made device-generic first; see `crate::memconv` docs.
